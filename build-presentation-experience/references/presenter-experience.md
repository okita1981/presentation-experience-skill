# Presenter experience design

## Document Story

Frame the document as a sequence of audience understandings:

- starting belief or open question;
- evidence or premise needed next;
- mechanism, option, or proposal;
- decision-relevant synthesis;
- source-supported landing.

This is not a page summary. Preserve the full document's logic while merging pages that perform the
same role. Record coverage separately.

## Cue test

A cue is designed only when all four are concrete:

> speaker line → operation → visible change → audience understanding change

If the speaker merely reads newly appearing text, or the operation changes nothing useful, redesign
the cue. If one operation asks the audience to understand several unrelated things, split it.

## Lifecycle

Use enter, persist, transform, minimize, accumulate, resolve, and retire deliberately. Carry an
element forward only when its continued presence helps the next explanation. The same element may
change form, but a transformation must not imply an unsupported change in identity or status.

## Presenter-led balance

The screen should neither replace the speaker nor become passive wallpaper. At each moment the
speaker must have a clear object to point to, operate, or use as shared evidence. The screen may be
quiet between operations.
