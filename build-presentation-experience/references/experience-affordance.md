# Experience Affordance Audit

Choose mechanisms from source structure, not from a desire to add motion. The fit class from the
fit check in SKILL.md tells you in advance which rows of this table the source can support.

| Mechanism | It changes | Required source basis |
|---|---|---|
| Reveal | accessible depth or basis | hidden detail, evidence, or layer |
| Compare | active subject or condition | comparable items with a stable axis |
| Filter | included set | explicit categories or criteria |
| Calculate | result | stated or arithmetically explicit formula and inputs |
| Simulate | scenario result | supported variable ranges and model |
| Traverse | current position in a structure | real hierarchy, sequence, or path |
| Inspect | detail while preserving overview | image, diagram, table, or dense object |
| Accumulate | confirmed set | items that genuinely build toward a later decision |
| Resolve | synthesis of earned material | a source- or presenter-supported landing |

## Choose by what the section claims

The table above says whether a mechanism is *possible*; the fit check says whether the document as
a whole affords operation. Neither says which mechanism a given section has *earned*. Read what the
section asserts, and let that decide:

| The section's claim | Mechanism |
|---|---|
| a conclusion resting on support | Reveal, with Inspect for the detail |
| the same set under another cut, measure, or ranking | Compare with Filter |
| one state against another | Compare, with the difference left visible |
| a driver and an outcome | Calculate, or Simulate across stated ranges |
| a shortfall and the measures that close it | Calculate or Simulate over the stated gap |
| a process, sequence, or argument that builds | Traverse with Accumulate |

Resolve is not chosen per section; it belongs to the document's landing, and only when the document
lands there.

A mechanism the data supports but the section does not assert is decoration with a click target. If
the claim cannot be named, the section is not yet understood well enough to operate — a finding,
not a delay.

For each candidate record: source reference; proposed operation; understanding before; understanding
after; verdict/risk. Use EXPLANATION_ONLY when no operation is earned.

Reject a candidate when the visible change is only a page, tab, card, fade, zoom, or decoration and
the audience's usable understanding stays the same.
